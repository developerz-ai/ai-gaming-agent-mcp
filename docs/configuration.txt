AI GAMING AGENT - Configuration Guide
=======================================

CONFIG FILE LOCATION
--------------------
  ~/.gaming-agent/config.json


CONFIGURATION SECTIONS
----------------------

SERVER SETTINGS
  host     - Bind address (default: 0.0.0.0 for all interfaces)
  port     - Server port (default: 8765)
  password - Authentication password (required)
  allowed_hosts   - Host headers accepted by /mcp
                    (default: localhost:*, 127.0.0.1:*, [::1]:*)
  allowed_origins - Origin headers accepted by /mcp
                    (default: http://localhost:*, http://127.0.0.1:*, http://[::1]:*)

VLM SETTINGS (Optional)
  enabled  - Enable local vision model (true/false)
  provider - VLM provider (ollama recommended)
  model    - Model name (e.g., qwen2.5-vl:3b)
  endpoint - VLM API endpoint

SECURITY SETTINGS
  allowed_paths    - Directories the server can access
  blocked_commands - Shell commands that are prohibited
  max_command_timeout - Maximum execution time for commands

FEATURE TOGGLES
  screenshot         - Allow screenshot capture
  file_access        - Allow file read/write
  command_execution  - Allow shell commands
  mouse_control      - Allow mouse automation
  keyboard_control   - Allow keyboard automation


HOST AND ORIGIN VALIDATION
---------------------------
The MCP endpoints (/mcp and /mcp/messages) validate the Host and Origin
headers of every request against server.allowed_hosts and
server.allowed_origins. Both default to loopback only.

  - Host not allowed: refused with 421 ("Invalid Host header")
  - Origin present and not allowed: refused with 403 ("Invalid Origin header")
  - The bearer token is checked first: an invalid token still returns 401
  - An entry matches exactly, or any host:port form of that host when it
    ends in ":*"
  - The wildcard covers host:port forms only: "192.168.1.100:*" matches
    "192.168.1.100:8765" but not the bare "192.168.1.100", which needs its
    own exact entry (otherwise it is refused with 421/403)
  - A remote PC must list its own address (e.g. 192.168.1.100:8765) in
    server.allowed_hosts, or every /mcp request from that client is refused
    with 421
  - Environment overrides (JSON array values):
      GAMING_AGENT_SERVER__ALLOWED_HOSTS
      GAMING_AGENT_SERVER__ALLOWED_ORIGINS
    These fill in the allow-lists only while config.json does not set them.
    Once config.json carries server.allowed_hosts / server.allowed_origins
    (a config.json written by "gaming-agent init" carries both), those
    entries are used as-is and the environment is ignored for them.


CLAUDE DESKTOP CONFIGURATION
----------------------------
claude_desktop_config.json only holds local stdio servers (command / args /
env); it does not accept sse-transport url / headers entries. Reach
the server's plain-HTTP SSE endpoint through the mcp-remote bridge (needs
Node.js 18+). Add MCP servers to the Claude Desktop config file:

Windows:
  %APPDATA%\Claude\claude_desktop_config.json

Mac:
  ~/Library/Application Support/Claude/claude_desktop_config.json

For each gaming PC, add an entry under "mcpServers":

  Name format: gaming-pc-1, gaming-pc-2, etc.
  command: npx
  args: -y, mcp-remote, http://<PC-IP>:8765/mcp, --transport, sse-only,
        --allow-http, --header, Authorization:${AUTH_HEADER}
  env: AUTH_HEADER = "Bearer <password>"

  --allow-http is needed because the server is plain HTTP; use it only on a
  trusted private network or VPN. The header goes through env (no space
  after "Authorization:") to avoid an argument-splitting bug on Windows.
  This config follows the mcp-remote and Claude docs and has not been run
  against a live client.

Claude Desktop "Connectors" (Settings > Connectors > Add custom connector)
need a public HTTPS URL with OAuth or no auth; they do not fit a LAN http://
address with a static Bearer header.

Claude Code connects directly (--transport goes before the name):

  claude mcp add --transport sse gaming-pc-1 http://<PC-IP>:8765/mcp \
    --header "Authorization: Bearer <password>"
  claude mcp list

Each PC must list its own address in its own server.allowed_hosts, otherwise
the remote connection is refused with 421 (see HOST AND ORIGIN VALIDATION).


NETWORK CONFIGURATION
---------------------
Default Port: 8765

Firewall Rules:
  - Allow inbound TCP on configured port
  - Allow from Claude's IP or your local network

For remote access over internet:
  - Use a VPN (strongly recommended)
  - Or set up reverse proxy with TLS


MULTIPLE PC SETUP
-----------------
Each gaming PC needs:
  1. Unique password (recommended)
  2. Same port or different ports
  3. Firewall configured
  4. Corresponding entry in Claude Desktop config

Naming Convention:
  gaming-pc-1 - First PC
  gaming-pc-2 - Second PC
  gaming-pc-N - Nth PC

ENVIRONMENT VARIABLES
---------------------
The environment supplies every setting that config.json does not define.
A value written in config.json wins over the environment for that setting.
A config.json written by "gaming-agent init" carries every field, so once
that file exists the variables below have no effect.

Each setting is nested, so a variable is the GAMING_AGENT_ prefix followed by
the section and the field, separated by a double underscore. Boolean
settings take true/false; list settings take a JSON array.

  Server:
    GAMING_AGENT_SERVER__HOST       - Server bind address
    GAMING_AGENT_SERVER__PORT       - Server port
    GAMING_AGENT_SERVER__PASSWORD   - Authentication password
    GAMING_AGENT_SERVER__ALLOWED_HOSTS - Allowed Host headers
    GAMING_AGENT_SERVER__ALLOWED_ORIGINS - Allowed Origin headers

  VLM:
    GAMING_AGENT_VLM__ENABLED  - Enable VLM
    GAMING_AGENT_VLM__PROVIDER - VLM provider (ollama)
    GAMING_AGENT_VLM__MODEL    - VLM model name
    GAMING_AGENT_VLM__ENDPOINT - VLM endpoint URL

  Security:
    GAMING_AGENT_SECURITY__ALLOWED_PATHS - Accessible paths
    GAMING_AGENT_SECURITY__BLOCKED_COMMANDS - Prohibited commands
    GAMING_AGENT_SECURITY__MAX_COMMAND_TIMEOUT - Command timeout (seconds)

  Features:
    GAMING_AGENT_FEATURES__SCREENSHOT - Allow screenshot capture
    GAMING_AGENT_FEATURES__FILE_ACCESS - Allow file read/write
    GAMING_AGENT_FEATURES__COMMAND_EXECUTION - Allow shell commands
    GAMING_AGENT_FEATURES__MOUSE_CONTROL - Allow mouse automation
    GAMING_AGENT_FEATURES__KEYBOARD_CONTROL - Allow keyboard automation

There is no debug switch and no logging configuration: the server reads no
GAMING_AGENT_DEBUG variable, and its log records go to the process output
(stdout/stderr) rather than to a log file.

The environment is also read when "gaming-agent init" writes the config
file, so a variable set before that first run is stored in config.json.
